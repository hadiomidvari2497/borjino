**Project:** Borjino — سامانه مدیریت ساختمان  
**Document Type:** Project Master Specification  
**Status:** مرجع اصلی طراحی و پیاده‌سازی پروژه  
**Architecture:** Raw PHP + MySQL + PDO  
**UI/UX Reference:** Nextable RTL Template  
**Functional Reference:** مشخصات فنی و نیازمندی‌های سامانه مدیریت ساختمان برجینو

---

## 1. هدف سند

این سند مرجع جامع پروژه «برجینو» است و باید مبنای طراحی، توسعه، اصلاح و گسترش سامانه قرار گیرد.

در پروژه برجینو دو مرجع اصلی وجود دارد:

1. **مشخصات فنی سامانه برجینو**
2. **قالب و طراحی Nextable**

این دو مرجع وظایف متفاوتی دارند و نباید با یکدیگر جایگزین شوند.

### 1.1 مرجع عملکرد

تمام قابلیت‌ها، قوانین کسب‌وکار، اطلاعات موردنیاز، منطق محاسبه شارژ، وضعیت‌ها، محدودیت‌های حذف و ویرایش، کاربران و سطوح دسترسی باید مطابق مشخصات فنی برجینو پیاده‌سازی شوند.

### 1.2 مرجع ظاهری

تمام ظاهر و تجربه کاربری پنل باید مطابق قالب Nextable باشد، شامل Layout، Sidebar، Header، Dashboard، Cardها، Formها، Tableها، Modalها، Alertها، Badgeها، Pagination، Login، Profile، Settings و تم‌های Light/Dark.

هدف «شبیه بودن» نیست؛ UI باید از زبان طراحی و الگوهای واقعی Nextable استفاده کند.

---

## 2. اصل بنیادین پروژه

> **Nextable = Source of Truth برای UI/UX**

> **مشخصات فنی برجینو = Source of Truth برای Functionality و Business Logic**

اگر قابلیتی در مشخصات فنی وجود داشته باشد ولی Nextable صفحه‌ای دقیقاً برای آن نداشته باشد، قابلیت باید با استفاده از کامپوننت‌ها و الگوهای Nextable پیاده‌سازی شود.

اگر Nextable قابلیتی داشته باشد که در مشخصات فنی برجینو تعریف نشده باشد، آن قابلیت بدون تصمیم مشخص جزو نیازمندی برجینو محسوب نمی‌شود.

## 10. ایجاد گروهی در سطح بلوک

فیلدها:

- ساختمان
- بلوک
- طبقه شروع
- طبقه پایان
- تعداد واحد در هر طبقه
- پیش‌شماره واحد
- متراژ پیش‌فرض

- توضیحات مشترک

سیستم از طبقه شروع حرکت کرده و به تعداد مشخص‌شده در هر طبقه واحد می‌سازد.

مثال:

```
طبقه 1 → 4 واحد
طبقه 2 → 4 واحد
طبقه 3 → 4 واحد
مجموع → 12 واحد
```

شماره‌گذاری به صورت ترتیبی انجام می‌شود.

بعد از ساخت گروهی، هر واحد باید مستقل قابل ویرایش باشد.

## 22. پارامترهای شارژ

- U = مبلغ ثابت هر واحد
- M = متراژ واحد
- rm = نرخ به ازای هر متر مربع
- N = تعداد نفرات ساکن
- rn = نرخ به ازای هر نفر
- F = هزینه‌های ثابت کل ساختمان
- V = هزینه‌های متغیر

---

## 23. ده روش محاسبه شارژ

### 1. واحدی

```
Charge = U
```

با پارکینگ و انبار:

```
Charge =
U
+ (Parking Count × Parking Rate)
+ (Storage Count × Storage Rate)
```

### 2. متراژی

```
Charge = M × rm
```

### 3. نفری

```
Charge = N × rn
```

### 4. نفر-متراژی

```
Charge = (M × rm) + (N × rn)
```

نسبت پیشنهادی 80 درصد متراژ و 20 درصد نفر است، اما باید قابل تغییر باشد.

### 5. واحدی + متراژی

```
Charge = U + (M × rm)
```

### 6. واحدی + نفری

```
Charge = U + (N × rn)
```

### 7. واحدی + نفر-متراژی

```
Charge = U + (M × rm) + (N × rn)
```

### 8. نفری + متراژی

```
Charge = (N × rn) + (M × rm)
```

### 9. واحدی + متراژی + نفری

```
Charge = U + (M × rm) + (N × rn)
```

### 10. هزینه‌محور

برای هر هزینه مشخص می‌شود که بر اساس چه معیاری تقسیم شود:

- مساوی
- متراژ
- تعداد نفر
- ترکیبی

مثال:

```
آب       → تعداد نفر
گاز      → متراژ
برق مشاع → مساوی
تعمیرات  → مساوی یا متراژ
```

# 53. قانون نهایی و غیرقابل ابهام پروژه

> **ظاهر برجینو باید مطابق Nextable باشد و عملکرد برجینو باید دقیقاً مطابق مشخصات فنی برجینو باشد.**

هیچ‌کدام نباید فدای دیگری شود.

اگر Nextable قابلیت آماده‌ای برای یک نیازمندی برجینو نداشته باشد، نیازمندی حذف نمی‌شود؛ بلکه با استفاده از Componentها و Design Language همان Nextable پیاده‌سازی می‌شود.

اگر Nextable قابلیتی داشته باشد که در مشخصات فنی برجینو وجود ندارد، آن قابلیت بدون تصمیم جدید وارد پروژه نمی‌شود.

بنابراین:

```
Nextable
    = UI/UX Source of Truth

Borjino Technical Specification
    = Functional / Business Source of Truth
```

این دو منبع در کنار یکدیگر، مرجع جامع پروژه برجینو را تشکیل می‌دهند.
